# Phase 37：DD Gate v2 报告 —— halt 吸收态修复研究（修正版）

- 时间: 2026-08-25（同日二次修订：修正恢复逻辑规格偏差 + 判定③单位 bug 后全量重跑）
- 改动: `app/engine.py` 仅 dd_gate 段（恢复机制可配；`recovery` 缺省 "default" 与 Phase27
  行为一致）+ 新增 `tools/backtest_dd_gate_v2.py`
- **结论先行: 四条判定全部不满足 → DD Gate 维持关闭，不给 config 建议值。**
  机制层面的核心发现：half_cap 是唯一真正消灭吸收态的恢复机制（占用率 ~81%→33.5%），
  cooldown/index_ma 仅小幅缓解（71~74%），三者 Calmar 均不达标；最接近达标的
  A_half_cap×score 卡在 ③（2019-20 窗口损失 4.16pp > 3pp 上限）。

## 1. 实现（params.dd_gate 扩展，config 默认不动）

```python
params.dd_gate = {"t1":0.06,"t2":0.10,"half_mult":0.5,
                  "recovery":"cooldown|index_ma|half_cap",   # 缺省 "default"=Phase27 原逻辑
                  "cooldown_days":10,     # R1：halt 满 N 日强制回 half
                  "half_cap_days":20}     # R3：half 最长 M 日强制回 normal
```
- **R0 default**：halt 在 dd>-T1×0.5 时回 half（Phase27 原逻辑）
- **R1 cooldown**：halt 满 N 日**无条件**强制回 half；half 仍按原 dd 条件恢复
- **R2 index_ma**：halt 仅当 sh000001 收盘站上自身 MA20（严格 PIT）才回 half——
  指数确认是**唯一**条件，不受 dd 位置限制
- **R3 half_cap**：取消 halt 态；dd≤-T1（含原 -T2 深度）进入/维持 half，
  half 满 M 日强制回 normal，若 dd 仍深则次日起重新计 M 天

### ★ 同日二次修订说明（诚实记录）
初版实现的 R1/R2 恢复判定被错误地放在 `dd≤-T1` 分支之后——深度回撤中两机制永不触发
（三种 recovery 占用率完全相同即为暴露点）。已修正为"恢复条件独立于 dd 深度评估"并
全量重跑；同时修正判定③的单位 bug（原始小数对比 3.0 恒真），以 `--rejudge` 重算。
本文所有数字为修正后版本。

## 3. 阶段1 结果（A=6%/10%；损失为相对现跑基线的百分点）

| 变体 | 策略 | ①回撤降≥20% | ②Calmar改善 | ③各窗损失(pp) | ④占用 | 通过 |
|---|---|---|---|---|---|---|
| default | score / board | 4✅ / 4✅ | 1 / 0 ❌ | ❌(+7.4@牛市) / ❌(+32.75) | 80.9%/65~91% ❌ | 否 |
| cooldown N=10 | score / board | 3 / 3 | 1 / 0 ❌ | ❌(+7.08@牛市、+3.18) | 71.4% ❌ | 否 |
| index_ma | score / board | 3 / 3 | 1 / 1 ❌ | ❌(+4.78@牛市) | 73.7% ❌ | 否 |
| **half_cap M=20** | **score** | 3 ✅ | **3 ✅** | ❌(+4.16@w0) | ✅ 33.5% | **否（最近）** |
| half_cap M=20 | board | 3 ✅ | 0 ❌ | ✅(除牛市+26.54) | ✅ 34.9% | 否 |

★ 吸收态修复实证（占用率 = halt + 0.5×half）：default ~81%、cooldown ~71%、
index_ma ~74%、**half_cap ~33.5%** —— 只有无 halt 态的 half_cap 达到 ≤40% 门槛。
cooldown/index_ma 虽脱离纯吸收态但仍超门槛近一倍。

## 5. 最终判定（规则事先写死）

- 修正后 **10/10 配置组合不满足** → **DD Gate 维持关闭，不给 config 建议值。**
- 分解看：① 回撤条件普遍达标（熔断确实降回撤）；② Calmar 只有 half_cap×score 做到 3/4；
  ③ 收益损失是普遍短板（尤其牛市机会成本）；④ 只有 half_cap 达标。

## 6. 还差什么（诚实分析）

1. **half_cap 已解决吸收态**（33.5% vs ~81%），剩余差距集中在 ③：
   温和震荡窗（2019-20）被"M=20 强制回 normal → 深度 dd 又立刻回 half"反复拉锯磨损
   -4.16pp。可行方向：M 自适应（按回撤深度缩放）、或恢复后加"最小正常持仓天数"防拉锯；
2. **board 与任何仓位型闸门天然不合**（牛市弹性被砍 26~33pp 且 Calmar 无改善）——
   若未来启用建议仅作用于 score 类低频策略；
3. index_ma 的指数线只覆盖到 2026-08-18 且 MA20 反应偏慢（占用率仍 73.7%），
   若采用需换更长历史指数源并调参（MA10/加权）。
