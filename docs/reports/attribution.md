## 1. 方法

- **回合构建**：全量 trades 按代码 FIFO 配对买卖；一笔买入被多次部分卖出（阶梯止盈）时，
  各笔卖出 pnl 按数量比例分摊回该买入。共 **3,077 个完整回合**
- **买入归因**：reason `[策略]评分N分: 信号A(+w)、…` 中取第一个非 ⚠ 信号为主动类别；
  规范化规则见 §2。统计每类：回合数、胜率、平均收益(pnl/买入金额)、盈亏比、
  总盈亏贡献占比、平均持仓天数
- **卖出归因**：按 reason 关键词分类（§2.2）；★卖飞成本 = 卖出日收盘 → 后第 5 交易日收盘
  涨跌幅均值（正 = 存在"卖早了"迹象）；窗口尾部无未来 K 线的卖出剔除并计数
- **交叉切片**：信号类别 × 四窗口；**持仓天数分桶**：按交易日索引差分 1 天/2 天/3–5 天/5 天+

### 4.2 最小日志补丁方案（仅方案；实盘代码需验收方批准，本次未动手）

改动点一处：`app/trader.py` `_event()`（L88–96），在文本日志外追加结构化成交事件：

```python
# Phase30 方案（未实施）：BUY/SELL 时补一条结构化审计记录
m = re.match(r"(买入|卖出)\s+(.+?)\((\d+)\)\s+([\d.]+)x(\d+)股\s*(.*)", msg)
if m:
    side_cn, name, code, px, qty, tail = m.groups()
    audit.record(kind="fill", event="fill", level=level,
                 side="buy" if side_cn == "买入" else "sell",
                 code=code, name=name.strip(),
                 price=float(px), qty=int(qty),
                 reason=tail.strip())   # 买入=评分+信号；卖出=退出规则原文
```

配套建议：① `state.manual_buy/manual_sell` 已有结构化字段，统一 event 名为 `"fill"`
并补 `side/reason`；② 卖出能拿到 pnl 时一并写入；③ `kind="fill"` 不影响哈希链与既有查询；
④ 存量无需迁移（account.json 可回补）。

## 5. 建议（证据→建议；不改任何代码）

**建议保留**
1. 涨停动量「很强/极强」两档 —— 四窗中两窗稳定盈利，board 主要利润来源
2. 阶梯止盈 / 冲高回落止盈 —— 兑现利润主力，冲高回落止盈几乎不留尾巴（fly5 仅 +0.25%）
3. 时间止损 —— 卖后 5 日均値 -0.26%（继续下跌），砍得对
4. MACD金叉 —— 正贡献但样本小（n=15），保留观察

**建议审查（给证据，供 Phase28 因子治理决策）**
1. **量价齐升**：出现频率最高的主动信号（46% 回合），扣费后 -28,956 元，且只在近 1 年
   牛市转正；建议评估降权或加趋势过滤
2. **涨停动量启动**（7~8% 档）：除 2019-20 外三窗皆亏（合计 -30,939），与"很强/极强"
   形成鲜明对照；建议提高打板最低涨幅门槛
3. **均线多头**：近 1 年胜率仅 25%、-21,804 元，与历史表现反转；建议排查近期失效原因
4. **RSRS看涨**：n=7 且全负，建议继续禁用状态观察
5. **3–5 天持仓段**：-136,581 元的最大亏损窟窿；建议研究 `TIME_STOP_DAYS` 前移或
   对第 2 天未走强的持仓加严退出（第 2 天是唯一规模化盈利段）
6. **止损**（-107 万元总额）：不是卖飞（fly5 仅 +0.27%），方向正确；亏损体量大源于
   前述低质信号进场太多——治理入口在买入端而非止损端

**局限声明**：股票池生存者偏差与前复权失真沿用引擎既有审计注记；成交概率模型
seed=42 固定，单次结果含随机性；模拟盘样本极小且缺卖出后行情，仅作方向性参照。
