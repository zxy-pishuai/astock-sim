## 2. 根因

1. **peak 污染**：实盘 `_exits_round` 与 `_fast_watch_loop` 均用行情快照 `high`（腾讯 f33 = **当日最高价**，无时段语义）无条件刷新 `pos["peak"]`。建仓后第一次刷新即把建仓前早盘高点记入持仓头 → 移动止损虚假触发。
2. **回测侧天然干净**：`engine.py`/`engine_minute.py` 的 `_check_exits` 在买入前执行，买入当日 days=0 不进检查段，peak 只用**建仓后交易日**的 bar high → 实盘与回测口径不一致（任务书判断属实，已用对拍单测 + 回测前后对比证实）。
3. **T+1 告警空转**：`_fast_watch_loop` 告警路径（原 L1789-1799）无 T+1 判定、无落单、无去重；冷却仅 15 分钟/类，跨小时挡不住重复。
4. **告警噪音**：冰点禁开仓在 `_scan_round` 每轮无条件 `_event`；竞价公示在 `_auction_round` 每轮 `_event`。

## 3. 修复内容（7 子任务逐项对照）

### 子任务① peak 只用建仓之后的价格 ✅

- 公共规则 `engine.update_peak_after_entry(peak, entry, obs_price, obs_time, entry_ts, ref_price)`：
  - 建仓时 `peak = entry_price`（trader `_buy` 原已如此），新增 `pos["entry_ts"] = time.strftime("%H:%M:%S")`
  - 刷新只接受 `obs_time >= entry_ts` 的观测（`obs_time < entry_ts` 的旧行情/缓存回填拒绝）
  - 实盘观测价 = **行情当前价 price**（当日场景用建仓后 tick 价累计 = max(entry, 建仓后各 tick high)；**禁止直接用当日 high**——因快照 high 无时段语义）
  - 异常值防御保留：`obs_price ≤ entry*2.0 and obs_price ≥ ref*0.5`
- 落地：trader `_exits_round` 刷新段、trader `_fast_watch_loop` b1/b2 段

### 子任务② 三处口径统一 + 对拍单测 ✅

- `app/engine.py`（日线回测）与 `app/engine_minute.py`（分钟回测）：peak 刷新加显式 `days >= 1` 守卫并调用公共函数（行为语义不变，显式化防回归）
- 对拍单测 `tmp/pack27/f2_peak_crosscheck.py`：构造"早盘冲高 12.54 → 回落 → 11:22:45 建仓 @11.9119 → 再回落"，**ALL-PASS**：
  - live 新行为 peak 恒=entry（早盘 12.54 未污染）；旧行为 peak=12.54（污染复现）
  - live 与 backtest peak 终值一致；移动止损触发时刻一致（均不触发）
  - 场景2（建仓后再冲高 12.50）：live/backtest 均接受、触发时刻一致；异常值防御与旧时间戳拒绝均 PASS

### 子任务③ T+1 冻结告警治理 ✅

- `_fast_watch_loop` b1/b2 接入 T+1 判定（对齐 `_sell` L739：`entry_date >= today` 冻结）
- 冻结文案：`🔒 <名称>(<代码>) T+1 冻结，移动止损将于次日开盘执行（触发价 <X>，现价 <Y>）`
- 去重：`_fast_watch_hint` 冷却键升级为 `kind|当日`（同一(标的,条件,交易日)当日只推一次）；主循环 `_exits_round` 用 `pos["trail_alert_date"]` 状态位当日一次

### 子任务④ 次日执行提前 ✅

- 主循环 `_exits_round` 循环开头：`pos["trail_pending"]` 挂起单在 `entry_date < today`（解冻）后**开盘第一笔行情**（09:30 首轮轮询）即执行，不再等 15 分钟扫描
- 挂起单含 `{reason, trigger_px, peak}`，成交后清状态位并记 KPI

### 子任务⑤ 回测同口径 ✅（回测侧本就干净，见 §4）

### 子任务⑥ 每日 KPI：止损滑点写 audit ✅
