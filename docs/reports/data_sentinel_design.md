# Phase 31 设计文档：数据质量哨兵（tools/data_sentinel.py）

- 状态：**已完成**（首次运行结果见 `data/quality_report.json`）
- 定位：把 Phase 20 的人工检查工具化、日常化——自动发现脏数据，而不是等它坑回测
- 红线：只读检查 + 新增文件；不自动修改 config / 数据库；纯标准库

## 1. 架构与数据访问

- 独立进程运行：`python tools/data_sentinel.py [--full-gaps]`
- SQLite 全程 `mode=ro` 只读连接；只 `import app.config`（路径/排除清单）与
  `app.trading_calendar`（官方日历），均为只读引用，不触碰引擎与写路径
- 单遍流式扫描 `kline(period='day')`（约 326 万行中 day 期子集）：
  缺口统计、volume=0 计数、复权跳变收集一次完成，全程 O(行数)
- 输出 `data/quality_report.json` + 终端摘要；默认缺口明细只详列最差 80 只，
  `--full-gaps` 保留全量计数表

## 2. 检查项设计

### ① K线缺口 + 日历一致性
- **经验日历** = 全市场 kline 日期并集（1853 天，2019-01-02 起）。原因：官方节假日表
  仅覆盖 2025–2026，直接拿它对照全史会对 2019–2024 年的每个法定假日误报
- 每只票在其自身 `[首日, 末日]` 内相对经验日历求缺失 → 新股上市前天然排除；
  最长连续缺口单独记录（区分"长期停牌"与"零星漏拉"）
- 停牌识别：任务约定用 volume=0 行识别。实测本库 **volume=0 行为 0 条** —— 本数据源
  的停牌表现为整行缺失而非零量行，因此"缺口"无法在本地与停牌完全区分，
  报告如实列出清单交人工判断（最差的 000670/600610/000792 恰是长期停牌/重整票，
  其中前两者已在 DATA_EXCLUDE_CODES）
- **日历一致性校验**：官方日历近 60 个交易日 vs 经验日历双向比对
  （官方有库无=未更新或漏拉；官方休市库有=节假表误配或脏数据）

### ② 复权异常（Phase 20 规则工具化）
- 跳变定义：同票相邻两日 `|次日开盘 / 当日收盘 - 1|`
- 阈值分层：
  - `medium`：超过板块涨跌停限制 + 0.5% 缓冲（主板 10.5% / 创业科创 20.5% /
    ST 5.5% / 北交 30.5%）—— 任务口径，噪音较大（大额除息、摘帽复牌也会触发）
  - `high`：超过 `2×限制 + 1%`（即 Phase20 的 >21%/31%）—— 高置信缺陷
- 豁免：上市后前 5 个经验交易日不判（Phase20 规则）；扫描范围 2019-01-01 起
- 交叉标注：候选是否已在 `config.DATA_EXCLUDE_CODES` / `qfq_repair_failed.json`

### ③ 股票名单新鲜度
`stock_list.json`（[code,name,price] × 5007）↔ kline 库 distinct code 双向核对。

### ④ min5.db 覆盖度
总行数 / 独立代码数 / 最新日期 / 最新日期行数（近 5 个交易日无更新即提醒）。

### ⑤ ml_pred 新鲜度
最后预测日期距今 >25 个交易日 → 提醒滚动训练（按官方日历计交易日）。

### ⑥ global_kline 积累
按 (market, sym) 分组：行数/首末日期/距今交易日数；`rows<30` 标记 thin；
单独输出美元指数（sym=DINIW）健康位——它是全球行情页的兜底依赖。

## 4. 异常处置流程（人工决定，工具不代劳）

引用既有流程：
- `docs/operations.md`「数据与备份」「年度维护」：数据库只读巡检、备份与年度维护节奏
- `docs/reports/clean_data_baseline.md`（Phase21）：人工确认 → 在 `app/config.py`
  `DATA_EXCLUDE_CODES` 增补代码并注明原因与日期 → 回测池/ML 训练/情绪历史自动过滤

对本次新增候选的建议动作（供验收方决策）：
1. `600262` / `600426`：先走 Phase20 的 `tools/repair_qfq.py` 修复路线（自实现前复权，
   校验通过才写库），修复失败再考虑入 `DATA_EXCLUDE_CODES`
2. medium 候选：抽样核对是否为除息/摘帽，确认属数据缺陷后再升级处理
3. global_kline DINIW：按 `docs/reports/global_market_data.md` 的数据源安排历史回补
