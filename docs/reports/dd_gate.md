# Phase 27：组合回撤熔断 —— 仓位闸门进入回测引擎

- 时间: 2026-08-24
- 结论先行: **判定不启用**。回撤相对降低条件普遍达标（A/B/C 变体 3~4/4 窗口），
  但 Calmar 改善仅 0~1/4 窗口，且每个变体的最差窗口收益损失达 −19 ~ −32pp
  （规则上限 3pp）。诚实负结果：熔断能把灾难窗口救回来（score W3 −36.95%→−9.61%），
  但代价是长期停机错过反弹，"每窗口收益损失≤3pp"全军覆没。

## 1. 状态机实现（app/engine.py，默认关闭）

- 跟踪组合总权益（含现金）历史峰值 peak；dd = equity/peak − 1，每日收盘后更新，
  次日买入时生效（天然 PIT）；只影响新开仓预算 `pos_cash`，不动存量持仓退出规则。
- 状态转换：
  - `dd ≤ T1` → **half**（新开仓资金 ×0.5）
  - `dd ≤ T2`（T2>T1）→ **halt**（当日 signals 置空停止开新仓）
  - 恢复：half 在 `dd > −T1×0.5` 时回 normal；halt 只先回 half（防震荡，多等一日）
- 并入买入预算链：指数择时乘数、情绪闸门乘数之后叠加；状态变化写 log_lines 复盘。
- `config.DD_GATE_T1/T2/HALF_MULT`（默认 None=禁用）；回测 params.dd_gate 显式覆盖。
- metrics 新增 `dd_half_days/dd_halt_days`；脚本侧记录 halt 日期列表供机会成本分析。

halt 天占比（占交易日）：

| 变体 | score 各窗口 | board 各窗口 |
|---|---|---|
| A | 84% / 95% / 90% / 70% | 84% / 87% / 61% / 74% |
| B | 84% / 95% / 90% / 54% | 83% / 84% / 55% / 0% |

halt 期间基线组合涨幅（正=错过的反弹，负=躲过的下跌）：

- 牛市窗口被 halt 错过的基线涨幅：score A/B +22.8%/+18.0%、board A **+36.2%**
- 熊市窗口躲过的基线跌幅：score W3 −28.9%/−29.8%（熔断确实实现了设计目标）
- **机制缺陷**：halt 后空仓 → 净值横盘 → dd 几乎无法回到 −T1×0.5 上方 →
  halt 成为近似吸收态（部分窗口 halt 占比 >90%）。恢复条件依赖"不交易也能涨"，
  与"停仓"自相矛盾。

## 5. 判定（规则事先写死，诚实执行）

规则：某变体 ≥3/4 窗口最大回撤相对降 ≥20%，且 ≥3/4 窗口 Calmar 改善，
且每个窗口收益损失 ≤3pp → 启用；否则维持关闭。

| 条件 | 结果 |
|---|---|
| 回撤相对降 ≥20%（≥3/4 窗） | A/B/C 多数达标 ✓ |
| Calmar 改善（≥3/4 窗） | 全部 0~1/4 ❌ |
| 每窗口收益损失 ≤3pp | 全部失败（最差 −19 ~ −32pp）❌ |

**判定：无变体通过 → `config.DD_GATE_*` 维持默认关闭，不改任何现有行为。**

### "卖在底部、错过反弹"情形分析（任务要求如实写）
1. 熔断触发点天然在下跌中后段（dd 连续恶化才过阈值），half→halt 两级触发后
   组合已承受大部分回撤，规避的只是尾部一段；
2. halt 后空仓横盘使净值曲线失去修复能力——2023-24 熊市躲过 −29% 的同时，
   也注定错过 2025-08 起的牛市前段（board W4 机会成本 +36%）；
3. D 变体（只 half 不 halt）收益损失最小但仍 −19pp，说明问题不在 halt 一级，
   而在于"以历史峰值为基准的回撤控制"对高波动策略天然过度保守；
4. 若未来重试方向：恢复条件改为"指数新高确认/固定冷静期后强制恢复"、或改为
   只对单笔回撤而非组合净值熔断。属新阶段范畴，本阶段不动。
