## 一、K6-1 前导零丢失：根因定位与修复

### 1.1 根因（实测实锤，非代码 int() 转换）

派单假设"`--verify` 路径把 `'000001'` 变成 `'1'`（大概率 `int()`/`%d`/numpy/json 往返）"。
逐层代码审查（bt_fingerprint.py / engine.py / db.py）+ 实证后确认：**Python 侧全程保持字符串**，
根因在 **PowerShell 命令行参数解析**：

```
$ x = 000001        → PS 数字字面量 → 1
py -c "print(sys.argv[1:])" --codes 000001,600519   → ['--codes', '1,600519']   ← 裸传参丢零
py -c "print(sys.argv[1:])" --codes "000001,600519" → ['--codes', '000001,600519'] ← 引号保零
```

后果链：`'1'`（无效代码）在 kline 查不到 → 该票被**静默跳过**（无报错）→ 回测结果
trade_count=0、total_return=0 但**照常落记录、照常"复现一致"**——"一致地错"，比报错更危险。

### 1.2 修复

`tools/bt_fingerprint.py`：
- 新增 `_norm_code(c)`：纯数字且 `<6` 位 → `c.zfill(6)`（`'1'→'000001'`；`'600519'`/`'sh000001'` 原样）
- `build_params` 中 `codes=[_norm_code(c) for c in args.codes.split(",") if c.strip()]`
- `codes_hash` 基于规范化后的字符串列表计算（原实现已如此，规范化后 hash 稳定）
- py_compile OK

修复前（`20260916_001028_2ec3`）：codes=`['1','600519']`、trade_count=**0**（'000001' 静默丢失）
修复后（`20260916_001417_b4d6`）：codes=`['000001','600519']`、trade_count=**4**、total_return=-0.0083

### 1.3 调用约定（报告注明，防复发）

PowerShell 下传 codes **必须加引号**：`--codes "000001,600519"`。代码层 zfill 兜底
（裸传 `1` 也能归一为 `000001`），但引号是正路。

  而 detail 文案（trader H4 生成）是"watchdog 断更 N 分钟"= **距上次心跳秒数**——两个口径并存。

  streak 口径统一为"**上次心跳到现在的秒数**"，与 detail 自洽。

### 6.2 改动（app/audit.py）

- 新增 `_g3_heartbeat_age(now)`：优先读 `tmp/watchdog_heartbeat.ts` mtime（trader 同源，
  streak=heartbeat age）；心跳缺失/异常时回退读 `tmp/h1_watchdog_state.json` 的
  **墙钟/单调钟双记**（`wall_ts`/`mono_ts`）：
  - wall_age = 墙钟年龄（断更表面时长）；mono_age = 单调钟年龄（Windows 单调钟睡眠期不前进）
  - `sleep_gap = wall_age - mono_age` → 休眠空档量化
  - 返回 `(age_or_None, sleep_gap)`
- `_g3_wd_stale_stateful`：streak = heartbeat age；心跳不可得 → 退回"首次断更"口径（可判定）；
  **sleep_gap ≥300s → 级别上限压到 WARN**（休眠空档非看护真死，不升级 ERROR/CRITICAL、
  不触发恢复），detail 标注"（含休眠空档 Ns，非看护真死）"。
- 级别阶梯/节流不变（10/30/60min；每级首条 + 每 3600s 重复当前级）。
