## 4. 任务 4 指定报告项：`watchdog_stale` 的 `streak_s` 恒为 0 说明

**定位**：`app/trader.py` L357-363（H4 断更 CRITICAL 节流）：
```python
audit.record(kind="daily", event="watchdog_stale",
             level="CRITICAL", streak_s=0,   # ← 首条恒 0
             watchdog_stale_reason=reason, ...)
```
**原因**：H4 的**首次告警**发生在"检测到断更超过阈值"时——此刻**断更总时长未知**（只有 `_wd_stale_start` 之后的下一条才带真实 `streak_s`，L368-369）。对照 `service_watchdog.py` 的 `streak_s`（watchdog 侧记录自身连续失败时长），两侧语义不同：trader 侧首条 0 是"发现时刻"标记，watchdog 侧是"持续时长"。
**建议**（按任务书不改 watchdog）：H4 首条应填 `streak_s=int(now - _wd_stale_start)`（若 `_wd_stale_start` 非 None），与后续条一致；当前首条 0 会让面板误读为"断更 0 秒"的 CRITICAL——**已列入报告建议，交数据道/验收方决定**（trader.py 属 F 道仅行情取数调用点，H4 语义改动超出本单范围）。
