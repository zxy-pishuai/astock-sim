## 3. 实现要点（对应任务书 1-5）

1. **single-flight**：三张独立在途表（通用/交易/展示），code 粒度去重（不同调用者部分重叠也去重）。
   硬超时 `QUOTE_SINGLEFLIGHT_WAIT_S=8s`，等待不持 `_lock`（只短暂持 `_inflight_lock`）。
   **两个关键竞态在测试中暴露并修复**：
   - checkout 的 wait/mark 分离 TOCTOU → 改为原子 `_inflight_checkout`；
   - 等待者捕获在途项与发起者 pop 的竞态 → 等待者直接持有 Event/ref 对象引用；
   - 重复 code 自等 → 入口 `dict.fromkeys` 去重。
2. **双通道**：`fetch_quotes_trading`（常驻池 6、5s 超时、8s deadline、TDX 优先、HTTP 并发、降级时 http_disabled）
   + `fetch_quotes_display`（2-worker 池、10s 超时）；共享 `_mem_quotes` 缓存，独立在途表。
3. **trader 调用点**：5 处实时判定路径全部切交易通道（L759/1333/1730/1984/2097），只改调用点。
   `fetch_kline`（L1177/1292 等）为历史K线非实时行情，不在双通道范围——任务书列出但判据不适用，如实说明。
4. **新浪回退**：串行改并发（`_fetch_sina_quotes` 用同一 pool），受整体 deadline 约束。
5. **停摆自愈**：`_update_trading_state`——交易通道过半缺失连续 3 次（`TRADING_FETCH_FAIL_STREAK`）
   → audit `quote_channel_degraded`(WARN) + 自动降级（只用 TDX/缓存、2s 短 deadline）；
   成功（缺失<50%）自动恢复。状态经 `trading_channel_state()` 只读暴露，trader 加
   `quote_channel_degraded` 只读属性；**server.py 的 trading/status 接入由 J 道完成**（本块红线禁改）。
