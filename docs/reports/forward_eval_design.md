# Phase 29：前瞻信号记账设计文档（forward_eval 口径说明）

- 时间: 2026-08-24
- 交付: `tools/forward_eval.py`（纯标准库，独立进程，不进服务）、`data/forward_eval.jsonl`
  （一行一日）、本文档
- 背景: 全球市场→A股映射提示（`app/global_market.py a_share_hint`）与盘前新闻行业筛选
  （`app/premarket_news.py`）无历史数据可回测 → 建"记账本"，收盘后逐日记录信号、
  次日结算实现收益，满 **60 个交易日**后 `--report` 输出命中率报告并给诚实结论。
- 红线遵守: 只新增文件；对两个信号模块**只 import 不修改**；服务未重启；
  数据缺失如实留空（`errors` / `pct:null` / `matched:false` 字段），禁止编造或回填。

## 1. 记账时点与锚日

- 工具每交易日晚间手动运行（后续可挂系统计划任务）。
- **锚日 = market.db 本地日线最大日期 T**（`MAX(date) WHERE period='day' AND length(code)=6`）：
  不依赖本地交易日历，且保证 T 的 K 线已落库。重复运行同一天自动跳过（幂等）。
- 两类信号都在 **T 日收盘后时点**采集，预测对象统一为 **T+1 日**实现收益：

| 信号 | 来源 | 内容 |
|---|---|---|
| ① 映射提示 | `gm.a_share_hint()` | 触发规则名 + 方向(up/down/flag)；此时全球隔夜/盘中行情对 A 股次日开盘有效 |
| ② 新闻行业 | `pn.sector_view()` | 按 net(利好-利空条数) 排序的 top3 利好行业、top3 利空行业 |

- AI 说明：新闻 AI 筛选为异步（`ai_pending`），工具最多宽限等待 75s；届时仍未出结果，
  如实记录 `ai_used:false, ai_pending:true`，该日可能只有规则法行业（net=0 无方向 → 不入选）。

## 2. 实现收益口径（T+1）

- **板块涨幅** = 该行业在 `data/sector_map.json`（系统既有通道，2910 票 × 49 传统行业）
  下成分股的**等权平均日涨幅**，个股数据取 market.db 本地日线（`close(T+1)/close(T)-1`）；
  两日缺任一收盘价的成分股剔除（剩余不足则该板块 `pct:null` 如实留空）。
  未引入任何新外部数据源（任务书允许的腾讯板块指数方案无需启用）。
- **大盘基准** = sector_map 全部成分股等权平均日涨幅。
  原因：库内指数线（sh000001 等）停在 2026-08-18 未再更新（仅 600 根），不可靠；
  等权全池与板块口径同源、无幸存者口径差。
- **超额** = 板块涨幅 − 大盘基准；**方向命中 hit**：
  - hint up/down：代理板块 T+1 涨跌方向与信号方向一致；
  - news_bull：T+1 上涨即命中；news_bear：T+1 下跌即命中；
  - flag 类（全球避险/汇率）：无方向，只记录涨幅与超额供参考，不计命中率。

## 3. 行业名对齐

新闻侧行业名（AI/规则输出，如"金融""机械"）与 sector_map 词表（"金融行业""机械行业"）
命名不一致。工具内置 `_match_industry()` 归一化（剥"板块/行业/概念"后缀 → 精确 → 唯一包含
匹配）；**歧义或不认识的名字返回 None 并在账本中记 `matched:false` 与原名**，
结算时该行业 pct 留空——不猜、不近似。实测："金融→金融行业"、"石油→石油行业"、
"半导体→None"(词表无对应，电子两类歧义)。

## 4. 报告与判定口径（事先写死）

`--report` 对每个信号族（各映射规则 / 利好合计 / 利空合计 / 单一行业≥若干次）输出：
触发次数 n、方向命中率、平均超额、平均次日涨跌。判定阶梯：

1. n < 60（记账日<60 或该信号触发次数过少）：**样本不足，继续记账，不下结论**；
2. 命中率 − 50% ≥ 1/√n 且平均超额 > 0：有正向信号迹象，可考虑小权重进打分系统并继续观察；
3. 平均超额 > 0 但命中率不显著：方向对、超额不够，不建议单独接入；
4. 其余：无可靠优势，不建议接入。

（1/√n 为二项比例约 1 个标准误的简化显著性线，n=60 时≈12.9pp，即命中率需 ≥62.9%。）

## 5. 账本格式（data/forward_eval.jsonl）

一行一日 JSON：
```json
{"date": "2026-08-21", "recorded_at": "...", 
 "hint": [{"rule":"半导体链","dir":"up","text":"...","proxies":["电子器件","电子信息"]}],
 "news_bull": [{"name":"金融行业","raw":"金融","matched":true,"net":2,"score":7,"count":3}],
 "news_bear": [...], "ai_used": false, "ai_pending": true, "errors": [],
 "realized": null}
```
结算后 `realized` 填入 `{"date":"T+1","bench_pct":...,"hint":[{rule,dir,items:[{name,pct,excess,hit}]}],
"news_bull":[...],"news_bear":[...]}`；结算逻辑幂等（只填 `realized:null` 的行），
漏跑的日子下次运行自动补结算——但信号本身不回填（当日没跑就没记，如实缺失）。

## 6. 首日记录（2026-08-24 运行，锚日 2026-08-21）

- hint：0 条触发（当时点无规则满足阈值）；
- 新闻：AI 未在宽限期内完成（`ai_pending:true`），规则法行业 net=0 → 无利好/利空入选；

## 7. 已知局限（诚实声明）

- 收盘后抓到的"盘前新闻池"是当前时点快照，非严格开盘前版本（缓存 TTL 300s）；
  验证的是该筛选逻辑的方向预测力，而非完整复刻实盘盘前时序；
- sector_map 为传统行业分类，部分主题（半导体/创新药等）无精确对应类目，
  映射提示的代理板块存在口径误差（已选最接近类目并在账本保留原文）；
- 等权板块涨幅未考虑流动性加权，小票噪声偏大；
- 样本天然前视偏差小（信号在前、实现在后），但新闻池本身有幸存者选择（AI 拒绝的中性新闻不入账）。
