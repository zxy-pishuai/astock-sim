## 1. 接线点地图（2026-09-01 读码，行号级）

### 1.1 共用接线点：`portfolio.compute_weights`

**关键事实：生产实盘与回测共用同一个权重函数**——

| 调用方 | 位置 | 代码 |
|---|---|---|
| 回测 `engine.py` | L655-658 | `wts = portfolio.compute_weights(closes_by_code, method=self.portfolio_method, target_vol=…, days=…)` |
| 实盘 `trader.py` | L681 | `pf_weights = portfolio.compute_weights(closes_by_code, method=C.PORTFOLIO_METHOD, target_vol=…, days=…)` |

- 函数本体：`app/portfolio.py` `compute_weights(closes_by_code, method, target_vol, days, max_leverage)`，
  内部按 method 分发 `equal | risk_parity | hrp | vol_target`（method 不在表 → 等权 fallback）。
- **爆炸半径（单一）**：加一个 method 分支即可被两处同时生效；不需要碰 engine/trader 的
  调用点以外的任何逻辑。**这就是"引擎语义不变"的最小改动路径的锚点。**

### 1.2 S1 权重 → 单仓现金的完整调用链（两处一致）

```
信号候选(signals[:slots]) → closes_by_code(仅收盘序列)
  → compute_weights(method=S1) → {code: weight}
  → 逐票: w_cap = min(1.0, weight, C.RISK_SINGLE_STOCK_PCT×0.95)   [engine L686 / trader L726]
  → pos_cash = cash × min(w_cap, pos_pct)                          [engine L689 / trader L727]
  → qty = int(pos_cash/px/100)×100（整手；qty<100 或涨停开盘跳过）  [engine L680 / trader L737-742]
```

- engine L646：`pos_cash = cash × pos_pct`（无权重时的默认单仓预算）；L684-689 有 `w` 时覆盖。
- trader L727：`pos_cash = acct["cash"] × (min(w_cap, pos_pct) if w_cap else pos_pct)`。
- **叠加闸门（保留，不因 S1 移除）**：指数择时乘数（engine L692 / trader L729）、情绪闸门乘数
  （engine L704 / trader L732）、回撤/涨停生态闸门（engine L609-643）——S1 只改权重层，
  这些乘数照常叠加在 `min()` 之后（只缩不扩）。

### 1.3 S1 需要的新数据：ATR14

- `compute_weights` 现有接口只收 `closes_by_code`（收盘序列），**不含 high/low** → S1 需要
  ATR 无法从接口现算。
- **ATR14 生产侧现成**：`app/indicators.py` L224 `def atr(klines, period=14)`。
- **接线补数据的最小路径（候选，供人类决策，非本块实现）**：
  1. 扩展 `compute_weights` 签名加可选参数 `atr_by_code=None`（None 时保持现行为）；
     调用点（engine L650-658 / trader L668-681）构造 `atr_by_code`（fetch_kline 拿 OHLC →
     `indicators.atr()`）。向后兼容、不破坏 equal/risk_parity/hrp。
  2. 或在调用点前把 ATR 写入一个模块级上下文（如 `portfolio._atr_cache`），S1 分支读取——
     更隐蔽但隐式状态不推荐。
- 推荐 **1**（显式参数，爆炸半径最小，接口干净）。
- S1 公式（与 W3 `sizing_lab.py` L136-139 同义，落盘锁定）：
  `tgt_daily = (0.15/3)/√244 ≈ 0.003201`；`atr_daily = ATR14(prev_date)/close(prev_date)`；
  `weight = min(0.30, tgt_daily / atr_daily)`。

### 1.4 S2 备选（机制更贴近"单笔风险预算"，W3 判 pass 但优先级次之）

`atr_scale = clamp(atr_daily/0.025, 0.5, 2.0)`；`stop_dyn = 0.05×atr_scale`；
`weight = min(0.20, 0.01/stop_dyn)`。接线点同 1.1，method 分支加 `risk_budget` 即可。

## 2. 参数定稿（从 bt_sizing_lab.json 引数，不重跑）

### 2.1 S1 实际暴露 ≈ 基线 1/3（引 JSON daily_vol）

| 窗 | S0 daily_vol | S1 daily_vol | S1/S0 暴露比 | S1 现金均值 | S0 现金均值 |
|---|---|---|---|---|---|
| 2019-20 | 1.014% | 0.435% | 0.429 | 71,137 | 33,304 |
| 2021-22 | 1.480% | 0.539% | 0.364 | 69,048 | 37,371 |
| 2023-24 | 1.448% | 0.557% | 0.385 | 62,223 | 30,878 |
| 牛市 | 1.405% | 0.463% | 0.330 | 74,872 | 43,885 |

→ **S1 实际暴露只有基线约 1/3（0.33-0.43），现金常态 62-75k**。这是 S1 削减伤害的机制来源：
低波票（如 ATR14 约 2-4% 的常规票）权重自然落在 0.30 cap 内；只有更低波动票才可能触 0.30。
任务书定性"实际暴露只有基线 1/3"在四窗全部成立。

### 2.2 目标波动档敏感性（若人类要更高暴露，用 15%×k 档；引 JSON + 605577 例，不重跑）

S1 权重公式对目标波动线性：`weight = min(0.30, k×(0.15/3)/√244 / atr_daily)`（k 为放大倍数）。
`tgt_daily(k=1) = 0.003201`。

| 档 k | 目标年化 | 605577 (atr_daily=4.6%) 权重 | 建议量(现金75,742) | 暴露 |
|---|---|---|---|---|
| 1（现 S1） | 15% | 0.070 | 400 股 ≈ 4,580 元 | 7.0% |
| 2 | 30% | 0.139 | 900 股 ≈ 10,306 元 | 13.9% |
| 3 | 45% | 0.209 | 1,300 股 ≈ 14,886 元 | 20.9% |
| 4 | 60% | 0.278 | 1,800 股 ≈ 20,612 元 | 27.8% |

**对照**：实盘该票当日实际暴露 ≈ 28.7%（1900 股 × 11.451 / 现金 75,742）≈ k=4 档。
→ 现行 `risk_parity + 0.30 cap` 对高波动票实际给出约"60% 目标波动"级别的暴露；
S1(k=1) 是约 4 倍削减。**参数建议**：保持 k=1 上影子线（先验证伤害控制是否如回测），
k=2-3 留给"若影子期暴露过低、收益恢复不达预期"时的人类决策，不做默认。

### 2.3 权重上下限 / 现金垫 / max_positions

- 权重上下限：`weight ∈ (0, 0.30]`（下限 0 由 ATR 缺失/无效时跳过该票体现；上限 0.30 保留，
  与现有 `position_pct=0.30` 语义一致）。引擎层仍有 `min(w_cap, pos_pct)` 二次钳制
  （engine L689 / trader L727），S1 权重不会突破单仓预算。
- 现金垫规则：**S1 天然留现金**（现金均值 62-75k，占 10 万账户 62-75%）——这是 S1 的核心机制，
  不是缺陷；无需额外"保留 N% 现金"参数。S3 的"显式 0.90 总仓"方案在 3 槽语义下退化 ≈ 基线
  （W3 §5 声明），故**不采纳**。
- `max_positions=3`：**保留**（W3 全程 3 槽）；"3 槽 → N 浮动槽"列为**远期选项**（需改引擎
  仓位语义，超本提案批准执行清单的最小改动路径），见 §5。
- 权重下限语义：若某票 ATR 异常高（atr_daily>0.30，如停牌后复牌跳空），weight 可能 <0.011 →
  建议量 <100 股被整手规则跳过（engine L742 / trader L742），属 S1 的正常降暴露行为。

## 6. 风险声明

1. **历史回测 ≠ 未来**：S1 的 MDD/收益改善来自 2019-2026 四个回测窗（PIT、196 口径），未来
   regime 变化可能不重复；接线首月实盘 MDD 超回测 **±5pp 属正常**，不作回滚唯一依据。
2. **选股层若后续转正，sizing 判据须重跑**：S1 的接线价值建立在"负 alpha 选股 + 降暴露削减
   伤害"上；若未来选股层 alpha 转正，vol-target 可能在正 alpha 上过度压制暴露、牺牲收益——
   **届时需按新判据重跑 sizing_lab（或改目标波动档 k）再评估**，不可沿用本次结论。
3. **实现风险**：S1 依赖 ATR14 的 PIT 口径（信号日 prev_date 前 14 根 TR）；实盘接线须确保
   ATR 用 `prev_date` 数据（防未来函数），且与回测同源（收盘价、复权口径一致——回测用冻结
   快照，实盘用实时库，需对齐复权）。
4. **暴露过低风险**：S1 实际暴露仅基线 1/3，现金均值 62-75%（10 万账户）；若选股层正 alpha
   恢复，暴露不足会成为瓶颈——§2.2 的 k=2/3 档是给人类的备用档，不默认启用。
5. **S3 不采纳**（0.90 总仓 + 0.30 cap 在 3 槽语义下退化 ≈ 基线，W3 §5 声明）。
6. **本报告为提案，零落地**：不改任何 `app/*.py`/config/计划任务；重放与影子表均只读。
