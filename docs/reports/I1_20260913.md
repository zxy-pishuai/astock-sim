## §0 背景与根因

`app/earnings.py` 的 `fetch_earnings(days)` 与 `_load()` 均以 `date.today()` 为基准取近 N 天，
`earnings_signal` 再用 `notice_date <= as_of` 过滤 → **历史 as_of 恒为空集**（PIT 可见性实测全 0），
所有历史回测中业绩因子恒贡献 0；而实盘（`as_of=None`=今天）因子生效 → **实盘/回测口径分裂**。

## §2 新旧口径差异说明（I 道铁律：提供旧口径开关，禁止悄悄改回测结果）

- **旧口径 = `as_of=None` 默认路径**：`fetch_earnings(60)` 联网拉近 60 天并入库，行为与原版一致
  （唯一差异：原单页 500 条截断 → 现 `_fetch_range` 分页全量，近 60 天 500→4014 条原始，修复"只存 500 条"截断）。
- **新口径 = `as_of=日期`（回测）**：窗口 `[as_of-60, as_of]`，**强制 offline 只读库、零 HTTP、零写库**。
- 口径选择完全由调用点显式传参决定，无全局开关猜测；`BACKTEST_OFFLINE` 仅作常量引用。
- **earnings 表结构变更**：主键 `(code, notice_date)` → `(code, notice_date, report_date, type, amp_lower, amp_upper)`
  （东财同一公告含多条不同指标行，原结构折叠丢信息；新结构全量唯一存储，离线/联网逐位一致的前提）。
