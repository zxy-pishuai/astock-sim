## 2. 🔴 B1｜暴露面 241/57 高估约 120 倍（P1，报告结论失准）
旧代码本就有 `amount_[i - 1] > 0` 守卫，因此**只有"前一根 bar amount>0"的零成交额日**才可能算出 `ar=0.0` 成假候选。D2 脚本（`tmp/pack25/s1_d2_exposure.py`）从未检查这一条件。

我用**两种互相独立**的方法复算，结论完全一致：

| 方法 | 结果 |
|---|---|
| 甲：逐条回查 D2 那 241 条清单的"前一根 bar amount"（SQL 直查） | prev>0 仅 **2** 条；prev=0 有 **239** 条 |
| 乙：按**生产精确判据**全库重算（`chg>=0.097` + 除权三向守卫 + `seq<5` 新股豁免 + `lbc==1` + 非一字） | 结构合格 254 条 / 59 票；其中 prev>0 仍只有**同样 2 条** |

真实暴露明细（两条都验到候选翻转）：
```
001359 2026-06-24  prev 2026-06-23  prev_amount=850,011,200
600584 2026-06-24  prev 2026-06-23  prev_amount=19,525,842,944
```

**根因（数据形态）**：amount=0 缺陷是**连续 5 天一段**写入的（H3c 已证 `_fetch_and_save(days=5)` 是"5 天历史重写器"）。所以"零段"内部只有**首日**满足 prev>0 → 真实暴露面 ≈ 零段起点个数，而不是零段长度之和。241 是"零段总长度"，被误当成了"候选数"。

**正确表述**：S1 的价值不在"消解 241 个历史假信号"，而在"堵住未来每一次零段起点"。历史上它一共只影响过 2 个票·日，且（班9 已证）26 笔真实成交命中 0 笔 → 风险等级从 P1 进一步降为 **P2 加固**，修复仍值得做，但优先级叙事要改。
