## §2 统一卖出定价函数 `app/exit_policy.py`（任务 1）

`exit_price(base_px, qty, code, side="sell", ctx=None)` —— 唯一共用函数，三步骤：

```
1) 可选固定滑点步 pre_slip（回测 legacy 的 base*(1-slippage)，engine.py:932；实盘传 0 跳过）
2) execution.execute_price(px, side, mcap, amount=px*max(qty,100), day_amount, impact)
   —— 唯一执行层（市值分档滑点 + 冲击成本），与实盘 P59 新口径（trader.py:905-907）对齐
3) 涨跌停钳制：ctx.limit_up/limit_down（>0 才钳制；实盘取 quote 字段、回测取 limit_prices 历史）
```

设计要点：
- **统一口径 = P59 新口径**（impact=True + 真实委托量）——与回测一致、与实盘观察期方向一致（P59 审计-D 就是为实盘最终切新口径铺路）。
- `pre_slip` 开关保留回测 legacy 双重滑点步（迁移前逐位一致；迁移后建议移除，见 §7）。
- 异常回退 `*(1-C.SLIPPAGE)` 与两侧现有回退语义一致。

**调用点迁移未做（按派单约束）**：trader.py/engine.py 的调用点改动需与 F/H 道协调，排在它们之后。本单只落地函数 + parity 证明，迁移清单见 §7。

## §4 对称性自动验证（任务 3 / 判据①）

`tools/test_i4_exit_parity.py`：**直接调用生产代码**（engine.Backtest.__new__ + 属性 stub 调 `_sell_price`；trader.TradingEngine.__new__ 调 `_buy_px(side="sell")`），与 `exit_policy.exit_price` 三方对比。用例矩阵 **216 组**（6 市值档 × 4 qty × 3 day_amount × 3 base_px，含贴近涨停/跌停钳制、impact 触发/不触发）。

```
用例数: 216（6 市值档 × 4 qty × 3 day_amount × 3 base_px）
A) 统一(回测ctx) vs 回测路径 : 最大偏差 0.00e+00  → 逐位相同 ✓
B) 统一(实盘新ctx) vs 实盘新路径: 最大偏差 0.00e+00  → 逐位相同 ✓
C) 实盘旧口径 vs 回测路径（现状不对称，pp）：p50=0.0999 p95=0.2995 max=0.2997
   实盘旧口径 vs 统一函数（pp）：p50=0.0999 p95=0.2995 max=0.2997
   收益影响估算：每笔卖出 100 万元计，p50 差 0.10pp = 999 元/笔
```

**判定**：
- A/B 两组 **0 处偏差**（统一函数与两侧新口径在全部 216 用例逐位相同）→ 判据①通过。
- C 组量化了**现状的不对称**：实盘现行旧口径（固定 1000 股假设 + impact=False，trader.py:893-896）比回测（固定滑点 + 分档滑点 + impact=True，engine.py:932-938）**卖出价高 0.10~0.30pp**——即实盘旧口径比回测乐观，回测成本假设更保守。这正是"注释声称对称但代码各写一遍"的真实代价。
- **修代码还是修回测假设**：结论是**修实盘**（切新口径）——P59 审计-D 的方向已是如此（BUY_PX_USE_NEW 观察期结束后由验收方切换）；回测双重滑点（pre_slip + 分档）在迁移统一函数时**建议去掉 pre_slip 步**（§7），使回测与实盘新口径单次滑点一致。

## §9 风险与回滚

- **风险 1（调用点未迁移）**：实盘/回测仍走各自旧代码，exit_policy 目前只有 parity 测试消费——**零生产影响**，但"统一"要等 §7 迁移后才在运行时生效。这是派单约束（F/H 协调），不是半成品。

- **回滚**：exit_policy.py 与 test_i4_exit_parity.py 均为新文件，删除即回滚；未改任何既有文件（本单零改动 trader/engine/audit/config）。
