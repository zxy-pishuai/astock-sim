## §4 落地修改（已 py_compile + --verify 实测通过）

**tools/service_watchdog.py**：
1. 新增 `_l2_degraded(detail)`：统一识别"短暂不可用"形态 = time_stale / TimeoutError / timed out / 10061 / 10060；
2. 新增 `batch_flag_active()`：读 `tmp/batch_running/*.flag` 且 mtime ≤3h 才算有效（崩溃残留自动失效，
   防永久豁免掩盖真死）；
3. 新增 `effective_recover_threshold()`：**l1=ok 且 l2 短暂不可用 且（cron 窗口内 或 批处理标记新鲜）→
   恢复阈值 3→6（约 30 分钟）**；其余情况维持 3。**l1=down 绝不放宽**（端口真死仍 3 次即恢复）；
4. main() 计数/日志改用动态阈值（日志标注"批处理放宽阈值"），删除原"完全豁免"分支。

**三个批处理 .cmd**（ml_scores_ledger_daily / risk_daily / forward_eval_daily）：
- 启动时写 `tmp/batch_running/<name>.flag`，结束（含 exit 路径）删除；纯 ASCII，GBK 代码页安全。

**实测自检**（py_compile + import 模拟 + watchdog --verify）：
- 服务当前健康：l1=ok / l2=time_age_0s / l3=audit_age_71s；
- 阈值矩阵：l1=ok+TimeoutError→6、l1=ok+time_stale→6、**l1=down+TimeoutError→3（不放宽）**、
  http_500（非短暂不可用）→3；新鲜标记→batch_flag_active=True。
