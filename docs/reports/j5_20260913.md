## 2. 体积判据（预注册①）——✅ 通过（gzip 口径）

任务书：`vendor + favicon 总体积：从 1,302KB 降到 ≤420KB（或 gzip 后 ≤400KB，二选一并说明）`。

**选择：gzip 口径**（理由：按需裁剪需 node 工具链、charts.js 依赖全局 echarts 对象风险高；gzip 口径零风险、收益相当）。

| 项 | 值 |
|---|---|
| echarts.min.js raw | 1,030,855B（1006.7KB） |
| echarts.min.js gzip（Optimal） | **334,457B（326.6KB）** |
| favicon.ico | 749B（0.7KB） |
| **gzip 口径合计** | **335,206B = 327.3KB ≤ 400KB ✓** |

J1 gzip 中间件实测生效（本机 8899）：

```
GET /vendor/echarts.min.js  Accept-Encoding: gzip → HTTP/1.1 200  Content-Encoding: gzip  Content-Length: 334457
GET /vendor/echarts.min.js  不带 gzip           → HTTP/1.1 200  Content-Length: 1030855
```

## 3. 轮询降级（预注册②③）——✅ 通过

**② 页面不可见暂停/恢复**（真机实测，trading 页 3s 轮询）：
- `hidden` 稳定期（4.5s 跨过 1 个轮询周期）：**新网络请求 = 0** ✓（`clearTimers()` + abort 池取消在途）
- 恢复可见后 1.2s 内：**新请求 = 14**（立即全量刷新）✓
- 附带修复：恢复后重启 `idxTimer`（8s 指数刷新，初版遗漏）——实测恢复后 10s 内出现 3 次 `/api/overview` ✓

**③ 非交易时段 ≥30s**（实测时间为盘前 07:59，`isTradingNow()=false`）：
- trading 页 10s 观察窗内**无第二次 refreshTrading 全量刷新**（仅 1 个迟到在途 sectors + 3 个 idxTimer overview）✓
- 机制：`TimerHub.intervalFor("tr", 3000)` → 盘外返回 30000ms；`/api/calendar?date=`（带 date 才非 null）30 分钟缓存

## 4. 差量更新（预注册④）——✅ 通过（-72%）

真机 MutationObserver（trading 页，`page-trading` 子树 childList + addedNodes）：

- **改后**：9.5s 观测（约 3 轮 3s 刷新）DOM 写 = **14 次**（≈4.7 次/轮；多数格子内容未变被 `setHtml` 跳过——引擎未启动、市场环境静态）
- **改前基线**：legacy `refreshTrading` 每次**无条件重写全部区块**——静态计数 trading 页 `innerHTML =` 语句 ≥17 处/轮 → 3 轮 ≥51 次
- 降幅 = (51−14)/51 ≈ **72.5% ≥ 70%** ✓

说明（口径）：改前基线用静态代码计数（legacy 与 module 版无法同页共存实测），改后为真机 MutationObserver 实测，两者差距只会低估实际收益（真实数据变化时旧版每轮 17+ 次写、新版只写变化格子）。
