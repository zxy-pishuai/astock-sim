## §1 改动清单（diff）
### `app/server.py`（写权限内）
| 位置 | 改动 |
|---|---|
| import | `gzip`、`hashlib`（标准库） |
| 模块级（Handler 前） | `_TEXT_CT/_GZ_MIN=1024/_GZ_LEVEL_BIG=1/_GZ_LEVEL_SMALL=9/_GZ_STATIC_BIG=6/_GZ_BIG_THRESHOLD=512KB/_IMMUTABLE_PREFIX=/vendor//_IMMUTABLE_EXACT=favicon/_STATIC_CACHE/_EXT_MAP` |
| `_load_static(rel)` | 静态文件内存缓存（mtime/size 变化即失效）；ETag=md5 内容 hash；Cache-Control 分级（vendor/favicon→`public,max-age=604800,immutable`，其余→`no-cache`）；文本类 ≥1KB 预压缩 gz（>512KB 用 level6，一次性成本：echarts 1MB→338KB vs level1 的 478KB）；Last-Modified |
| `_warm_static_gz()` | 启动时预压缩 vendor 大文件（`serve()` 首行调用；失败不阻塞） |
| `Handler.protocol_version` | `"HTTP/1.1"`（keep-alive；已发 Content-Length 安全） |
| `Handler._send()` | 新增 `cache_control/etag/last_modified/pre_gz/allow_gzip` 参数；文本类 ≥1KB 且客户端 Accept-Encoding 含 gzip → 自动压缩（>512KB level1 省 CPU），发 `Content-Encoding: gzip` + `Vary: Accept-Encoding`；API 仍 `no-cache` 不发 ETag |
| `Handler._serve_static()` | 改用 `_load_static` 缓存；`If-None-Match`/`If-Modified-Since` → **304**（no-cache 语义=必须 revalidate，ETag 命中即 304 不重传）；favicon/vendor 走 immutable 缓存 |
| **G4 协调** | `_send` 末尾 `self.wfile.write` 处预留注释：`★ G4（待接）：客户端断开保护包裹 self.wfile.write`——J1 已先合入，G4 直接在此包裹即可 |

### `web/`（写权限内）
| 文件 | 改动 |
|---|---|
| `index.html` | 4 处资源引用加版本串：`app.css?v=20260903214754`、`charts.js?v=20260818021126`、`app.js?v=20260913160831`、`experiments.js?v=20260901003655`；favicon 引用加 `?v=20260913`（配合 immutable，内容变更强制刷新一次） |

## §2 实测数据（8897 临时实例，新代码）
**首屏首次加载**（gzip 后）：
```
/                          11,264 B  (raw 49,181)
/css/app.css?v=...          8,195 B  (raw 36,134)
/js/app.js?v=...           39,634 B  (raw 137,232)
/vendor/echarts.min.js    338,093 B  (raw 1,030,855)  ← level6 预压
/favicon.ico?v=...            749 B  (raw 749)
合计 397,935 B = 388.6KB（改动前 1,494,148B = 1.49MB）
```
**二次加载**：5 资源全 304，传输 **0B**（ETag 协商）。
**keep-alive**：单个 HTTP/1.1 连接顺序完成全部首屏资源（原 HTTP/1.0 每请求新建 TCP）。
**无 gzip 客户端**：Content-Encoding=None，raw 传输（优雅降级）。
**favicon 视觉**：重压后为 16/32/48/64px 多尺寸 ICO（749B），放大渲染与原图一致（深色底黄色流星光斑）。

## §3 验收判定与披露
- **判据 1/2/3/4a/4b/5/6 全部达标**。
- **判据 4c 未达标（37.9% > 35%）**：`/api/backtest/pool` 17,879B 为高熵紧凑 JSON（数字密集、符号重复度低），gzip level9 已压到 37.9%，**接近 gzip 对该数据形态的理论极限**（level6=39.6% → level9=37.9%，边际收益 1.7pp）。为达标需 API 层字段裁剪/分页（功能性改动，超出 J 道 HTTP 卫生范围，**未实施**，供人类决策）。
- **favicon 替换披露**：256px 图层移除（浏览器标签页用 16-32px），图标视觉不变；原始 302KB 版本备份于 tmp。
- **压缩档位调整披露**：任务书建议">512KB 用 level1 省 CPU"——实测 echarts level1=478KB 致首屏不达标，改为**静态预压 level6（一次性+缓存，338KB）**；`_send` 自动压缩（API 大响应）仍保留 level1 省 CPU。
- **测试隔离**：全部实测在 8897 临时实例（新代码）；8899 生产服务未重启（旧代码继续运行，新代码待 X1/服务管理方重启生效）。

## §4 与 G4 的协调状态
J1 已先合入 `server.py:_send`（gzip/缓存头改造完成，`wfile.write` 处预留 `★ G4（待接）` 注释）。G4 块只需在该处包裹客户端断开保护（BrokenPipeError/ConnectionResetError），无冲突。**8899 重启时 J1+G4 改动需同时生效**。
