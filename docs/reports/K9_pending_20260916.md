# K9 报告：前端消费 `pending` 占位（2026-09-16）

## 一、结论速览
- **fetchJson 统一识别 `{pending:true, retry_after_ms:N}`**：自动按 N 重试（上限 5 次 / 总预算 30s），期间骨架屏、不覆盖已有数据；耗尽抛 `pendingTimeout` → `.err-banner` + "点此重试"，**不留空白页**。
- **真机浏览器验证（CNGC bu）通过**：6 个目标页面全部渲染正常、控制台 **0 未捕获异常**。
- **生效方式**：静态文件为 `no-cache`（ETag/304 协商）→ 改动**立即生效**（已实测 `window.fetchJson/uiShowErrBanner/loadWithPlaceholder` 均在）。

## 二、改动清单（文件:行号，diff 级）

### `web/js/core/api.js`（重写，19→120 行）
1. **`fetchJson` 增强**：
   - 响应 `pending===true` → 按 `retry_after_ms` 等待后自动重试（上限 `FETCH_PENDING_MAX=5` 次、总预算 `FETCH_PENDING_TOTAL_MS=30s`，单次请求超时 `15s` 防一次吃掉预算）；
   - 重试耗尽 → 抛 `pendingTimeout` 错误（带 `url`，页面可识别）；
   - **占位响应绝不当业务数据返回**（pending 永不穿透）；HTTP 错误照抛。
2. **加载态辅助**（挂在 window）：
   - `uiShowSkeleton(el)` / `uiClearSkeleton(el)`：复用 J5 `.skeleton` 样式；
   - `uiShowErrBanner(anchor, retryFn)`：复用 J5 `.err-banner` 样式 + "点此重试"按钮；
   - `loadWithPlaceholder(el, loader)`：骨架屏 → 数据 / 失败 → err-banner + 重试。

## 四、风险与回滚
- **风险**：重试最长 30s——极端下用户等待上限 30s 后见 err-banner（可接受，原行为是立即空白）；每次重试间隔 ≤5s（服务端 retry_after_ms 受控）。
- **回滚**：`git checkout -- web/js/core/api.js web/js/pages/tactics.js web/js/pages/pnews.js web/js/pages/global.js web/js/pages/trading.js`，静态文件 no-cache 立即回旧。
- **生效**：已生效（无需重启服务，已实测）。
