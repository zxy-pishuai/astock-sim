## 一、结论速览
- **主凶实锤**：overview 请求线程同步取 600 只实时行情（TDX→腾讯→新浪补缺链），冷态/降级时 8s×N 批。
- **打点归因（首轮真实数据，audit `overview_phase_latency`）**：`quotes_ms=6081.7ms`（主凶，占 95%+）、`indices_ms=249.6ms`、`breadth_ms=0.1ms`、`regime_ms=0.0ms`、`quality_ms=12.8ms`。
- **改造后请求线程零取数零重算**：直接读后台单飞刷新的内存快照；TDX 降级/超时时返回旧值 + `stale=true`，绝不阻塞。
- **生效方式**：服务端改动需服务重启后生效（铁律：不自行重启，由用户决定）；前端无涉。
- 判据：②（TDX 降级仍秒回）**单元验证通过**；⑤（stale 机制）**通过**；①③④ 为**待生效验证项**（需服务重启后盘中数据，如实标"待观察"，不装完成）。

## 三、改动清单（文件:行号，diff 级）

### `app/server.py`
1. **overview 分支**（原 L1152-1173 → 现 2 行）：`self._json(_overview_payload())`——请求线程零取数零重算。删除原同步 `fetch_indices`/`fetch_quotes(600)`/`calc_breadth`/`get_regime`/`quality_alert_summary` 五连。
2. **新增 K8 快照层**（`serve()` 前）：
   - `_OV_SNAP`（内存单例：ts/data/phases/refreshing/quality 缓存）+ `_OV_LOCK`；
   - `_ov_compute_once()`：一轮完整刷新，**各段打点**（indices/quotes/breadth/regime/quality_ms），任何段失败不阻断整体；
   - `_ov_refresh_worker()`：写快照 + 节流（60s）写 audit `overview_phase_latency`；
   - `_ov_start_refresh()`：**单飞**（refreshing 标记防并发线程）；
   - `_overview_payload()`：冷态 → `{pending:true, retry_after_ms:3000}`（客户端按 K9 重试）；age>10s → `stale=true`（判据⑤）；age>5s → 后台续新（SWR）；
   - `_start_overview_refresher()`：daemon 轮询（每 5s 检查续新）。
3. `serve()`：启动时调用 `_start_overview_refresher()`（daemon，不阻塞启动）。
4. 常量：`_OV_REFRESH_INTERVAL=5.0`、`_OV_STALE_AFTER=10.0`、`_OV_QUALITY_TTL=60.0`（quality 段读 audit jsonl 较重，60s 节流重算）、`_OV_AUDIT_INTERVAL=60.0`（打点防刷屏）。

### `app/datafeed.py`
1. `fetch_quotes_overview`（L704 起）升级 **SWR**：有缓存（无论新旧）一律先返回；仅 age>30s 时后台单飞续新（daemon 线程写缓存），**本次调用不阻塞**；无缓存（冷态）才同步取数（调用方为后台线程，阻塞无妨）。
2. 新增 `_start_overview_bg_refresh()`：单飞续新（同一 key 只允许一个在途）。

## 五、风险与回滚
- **风险**：快照是 5s 级异步更新——极端情况下响应滞后 ≤10s（stale 标记兜底），与判据⑤一致；quality 红条延迟 ≤60s（节流），可接受。
- **回滚**：`git checkout -- app/server.py app/datafeed.py`（仅本单两文件），服务重启即回旧行为。
- **生效**：需重启服务（watchdog 重启或用户手动）→ `serve()` 执行 → 快照线程启动。**本单未自行重启**。
