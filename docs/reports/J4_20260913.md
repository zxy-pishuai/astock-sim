## §7 可选 CI 方案（方案与风险，不擅自创建计划任务）

**方案**：Windows 计划任务在夜间 git 提交（TianjiGit_Nightly 23:50）**之前** 23:40 跑 `py -3.13 tools/preflight.py --scope <nightly_scope.json>`；失败 → audit 写 CRITICAL + **跳过提交**（保留脏工作区供人工检查），并在次日报告中体现。

**风险与取舍**：
1. 跳过提交会导致后续 AI 的改动也滞留（脏工作区累积）——需人工仲裁，这是特性（阻止坏提交）也是代价（阻塞流水线）；
2. preflight 的 `--scope` 需 nightly 维护一份全局白名单（随派单文档更新）；
3. 冒烟集当前 0.7s，放入夜间门禁无性能负担；若未来测试膨胀，建议先拆"慢测试"标记再接入；
4. 计划任务与现有 watchdog/夜间批处理错峰（23:40 与 20:20~20:32 批处理、15:10 收盘更新均不冲突）；
5. **由用户决定是否落地**——J4 不擅自创建计划任务（派单红线）。

**建议先行项**：先让 5 个并行 AI 用 `--scope` 跑 3 天（人工把关），稳定后再自动化。
