# Phase 25：ML 评分加权因子报告（ml_pred → 打分层加权，不改股票池）

- 时间: 2026-08-24
- 目标: 把 `ml_pred` 分数作为综合评分的一个加权因子（保留全池扫描，不截断池），
  以 weight ∈ {0, 0.5, 1.0, 1.5} 回测验证并按事先写死的规则诚实判定
- 结论先行: **score 策略 2/4 窗口改善（未达 3/4 门槛），2021-22 熊市窗口 -20~-24pp 恶化
  → 不接入；`ML_RANK_WEIGHT` 默认保持 0.0（关闭）**

## 1. 实现与命名说明

### 1.1 命名（与任务书的偏差，重要）
任务书要求新增 `ML_SCORE_WEIGHT`，但该名字**已被 Phase 4.6 占用**
（`config.ML_SCORE_WEIGHT = 8`：`scoring.ml_score_bonus` 读 ml_scores.json 的分位加分幅度，
默认关闭的旧路径）。为不改动任何既有语义，本阶段因子命名为：

```python
# app/config.py
ML_RANK_WEIGHT = 0.0   # 总开关兼强度（默认关闭）；回测档位 0.5/1.0/1.5
ML_PRED_BONUS_SCALE = 8      # K 校准值
```

### 1.2 加分公式与 K 校准
- 公式：`加分 = (score - 0.5) * 2 * weight * K`（score∈[0,1] 截面 rank，0.5 中性）
- K 校准过程：读 `scoring.score_stock` 现有综合分量级——`SCORE_WEIGHTS` 全部正向分量合计
  **148 分**（量价 20+突破 20+均线多头 15+RSRS 15+MACD 10+RSI 10+缩量回踩 5+回踩企稳 5+
  金叉 5+海龟 10+加速 5 + 量价深度 corr10/slope5/vwap5/surge8）。取 **K=8**：
  weight=1.0 时最大加减分 **±8 分 ≈ 148 × 5.4%**，落在"占总评分 5%~8%、个位数级别"目标带；
  weight=1.5 时上限 ±12 分（≈8.1%，仍为个位数量级的边际影响）。

### 1.3 PIT 与缓存（严格按任务书要求）
- 候选 (code, t)：只取 `ml_pred` 中 **date ≤ t 的最新一日全截面**（两次 SQL：MAX(date) + 当日
  SELECT，sqlite3 只读连接）；**按日缓存 `{code: score}` 字典**（`_ML_PRED_DAY_CACHE`），
  禁止逐票逐日查询——回测全程每换一日仅 2 次查询
- 无预测记录的票**加 0 分**（不加不减、不剔除，避免覆盖偏差）；如 2019-01~08（覆盖起点前）
  与 2026-08-14 之后（预测终点后沿用最后一日截面，仍 PIT 合规）
- 接入点：仅 `score_stock`（综合评分）尾部追加，weight=0 时整段跳过零开销；
  **未改任何现有因子计算**。`score_board` 未接入（见 §5 board 定位的说明）
- 冒烟验证：w=0 恒 (0,[])；PIT 回落正确（2026-08-18 → 用 08-14 截面）；当日缓存命中

## 2. 回测对齐（先修对齐再谈结果——实际发生了）

初跑 weight=0 **不对齐**（board 2019-20 得 -8.85%/843 笔 vs 基线 -11.77%/628 笔）。排查：
1. 历史数据指纹校验（当前库 vs Phase21 备份 `data/backups/20260823_151504/market.db`，
   池内全部 code 2019-2020 的 count/sum(close)/sum(volume)/sum(amount)）：**0 差异** → 数据无漂移
2. 变量矩阵（资金/滑点/名单/池）均无法复现 → 定位到 `_load_data` 的 `fetch_quotes()`
   实时行情：基线运行时该调用为空（mcap 走"成交额×20"近似），现在有网导致市值分档滑点不同
3. **修复**：worker 进程内 `eng.df.fetch_quotes = lambda codes: {}`（monkeypatch，不改源码），
   并采用与 Phase23 worker 相同的参数：
   score={bt25,pos3,pct0.30}、board={bt40,pos2,pct0.25}，slippage=0.001，capital=10万

**对齐结果（weight=0 vs data/bt_clean_results.json，两策略 8 窗口全部精确一致）**：

| 策略 | 窗口 | 收益 | 交易数 | 最大回撤 |
|---|---|---|---|---|
| score | 4/4 | 全部一致 (-7.65/-21.59/-36.95/+30.68%) | 1331/1540/1332/809 ✓ | ✓ |
| board | 4/4 | 全部一致 (-11.77/-6.65/-1.66/+27.30%) | 628/747/616/448 ✓ | ✓ |

## 3. 结果对照（top500 全池，Δ=相对各自 weight=0 基线）

### score（唯一受因子影响的策略）

| weight | 2019-20 | 2021-22 | 2023-24 | 近一年(牛市) | 改善/持平数 |
|---|---|---|---|---|---|
| 0.5 | **+2.15pp** | **-20.08pp** | -4.64pp | **+14.20pp** | 2/4 |
| 1.0 | **+1.99pp** | **-20.92pp** | -4.31pp | **+14.39pp** | 2/4 |
| 1.5 | -3.59pp | **-23.80pp** | +0.35pp | **+14.39pp** | 2/4 |

交易数变化全部 <1%（1322~1543 vs 基线，远低于 15% 上限）→ 打分加权确实保留了交易结构。

### board（对照，不受因子影响）

board 策略走 `score_board`，本阶段因子未接入该函数（任务书限定"综合评分"）→ 各 weight
结果与基线完全相同（Δ=0）。它在网格中充当**运行器确定性对照组**：4 权重×4 窗口 32 组数字
与基线逐一相等，证明并行 worker 无漂移。

## 4. 判定（规则事先写死）

启用条件：某 weight 使 ≥3/4 窗口 Δ≥-1pp，且牛市窗口恶化 ≤2pp，且交易数变化 <15%。

| 配置 | ≥3/4 改善/持平 | 牛市 Δ≥-2pp | 交易 <15% | 判定 |
|---|---|---|---|---|
| score w=0.5 | ❌ (2/4) | ✅ (+14.2) | ✅ | **不通过** |
| score w=1.0 | ❌ (2/4) | ✅ (+14.4) | ✅ | **不通过** |
| score w=1.5 | ❌ (2/4) | ✅ (+14.4) | ✅ | **不通过** |
| board w=* | 平凡真(Δ=0 无操作) | — | — | **不构成接入依据** |

**结论: 不接入。** `ML_RANK_WEIGHT` 默认保持 **0.0**。
- 诚实备注：board 行在字面规则下"通过"，但那是因子对其完全无效果的平凡真，不能作为接入
  依据；唯一受影响的 score 在三个档位均为 2/4，规则未满足
- 归因：ML rank 在牛市窗口有真实增量（近一年 +14pp 且单调随 weight 饱和于 +14.39），
  但在 2021-22 熊市大幅放大亏损（-20~24pp）——与 Phase21 "score 仅牛市可用"的结论同向：
  该因子是**牛市增强项**而非全天候因子，直接常开不可取
- 可能的后继方向（未实施）：牛市状态闸门（如指数/情绪条件）下才启用权重，需另立阶段验证

## 5. 任务书差异备注
- 任务书写"共 12 组"，实际网格为 weight(4) × 策略(2) = **8 组配置 × 4 窗口 = 32 个回测单元**，
  已完整覆盖指定参数空间
- 因子最终命名 ML_RANK_WEIGHT（旧参数组/旧函数一律不动；§1.1 说明）
