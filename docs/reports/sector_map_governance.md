## 1. 根因

`app/sector.py::_fetch_cons` 对每板块分页数做了 `min(pages, 5)` 硬截断：

```
pages = ceil(total/80)；单页上限 5 页 = 最多取 400 只/板块。
140 只的行业完整；400+ 只的行业只能拿到前 400。
28 个行业存活、21 个行业成员大半被截掉后从映射里消失 ——
由此出现"49 行业收窄到 28 行业 / 2,910→1,765 票"，forward_eval 的
板块等权涨幅基准与大盘基准随之系统性失真。
```

08-27 凌晨 03:26 服务 warm_up 用旧逻辑再次复现了缩水版映射（即修复前基线）。

## 2. 修复内容

### ① 完整分页拉取（要求①）

`_fetch_cons(label)` 重写为按 `Market_Center.getHQNodeStockCount` 返回总数动态分页：

- 总数接口失败重试 3 次（间隔递增）；拿得到则页数 = ⌈total/80⌉，**取消 5 页截断**
- 单页拉取失败重试 2 次；重试耗尽**保留已取到的成分并止于该板块**（容错不外抛）
- 外层 `_fetch_all_cons` 维持原有"单板块 try/except 不影响整体"结构
- 兜底防死循环：总数不可得时退化为"短页(返回条数<80)即尾页"+ 40 页硬上界
- 每 80 页间 0.25s 温和限速；同板块去重（保持首现顺序）
- 新增诊断遥测 `_last_fetch_stats[label]={total,got,pages}`，供核验抓残余缺口

### ② 写回缩水保护（要求②）

新增 `_shrink_guard(old,new)`：新映射代码数 < 旧文件 × **75%** → 判定疑似拉取不全：

- **拒绝写回磁盘，也不覆盖内存缓存**（旧映射继续作为权威口径服务 scoring/forward_eval 等）
- 写审计告警：`audit.record(kind="daily", event="sector_map_shrink_blocked", level="WARN", old_codes, new_codes, threshold=0.75)`；审计链不可用时兜底 stdout 告警
- 边界正确性：无旧文件（首次生成）不拦截、旧文件为空不拦截、比较异常视为放行
- **单元测试 6 用例全过**：首次生成✓ / 空 dict✓ / 100→74 拦截✓ / 100→75 恰在阈值放行✓ / 100→76 正常✓ / 真实场景 1765→1320 拦截✓
