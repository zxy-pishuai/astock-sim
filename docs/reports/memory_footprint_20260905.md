## §2 🔴 架构一致性发现：运行链已不再是"纯标准库"

- 项目全书第一部明写："**后端纯 Python 标准库**（运行链零第三方依赖）"。
- 实测 `app/tactics.py:35` **`import numpy as np`** —— 这是 R2-P0.1（9/4 为解板块首刷超时）为向量化而引入，并在 22:00 起随常驻服务加载。
- 三重代价：① **文档 ≢ 代码**（三方一致原则的文档面被破，后续任何"零依赖"前提的部署/迁移判断都会错）；② **内存**：numpy 常驻 + 全宇宙（2526 票）向量化数组（`sliding_window_view`/cumsum 的多列 float64）留在**常驻服务进程**内，不随扫描结束归还 → 这是 1,577MB 峰值与 2,387MB 私有的主要来源；③ 运行时依赖面扩大：换机器/升级 Python 时不再"拷了就能跑"。
- 定性：**不是 bug，是未登记的技术债**。R2 当时的性能结论（冷扫 24s→1.2s、向量化提速 82.9%）依然成立且有用，但"零依赖"这条卖点已经失效，必须二选一：改文档 + 加内存护栏，或把向量化挪出常驻进程。
